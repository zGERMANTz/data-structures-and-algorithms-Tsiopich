## Реализованные компоненты

### 1. Рекурсивные функции

**1.1. Факториал**

Рекурсивная реализация факториала с базовым условием для n = 0 и n = 1.

**Сложность:** O(n) — глубина рекурсии равна n.

**1.2. Числа Фибоначчи (наивная рекурсия)**

Классическая наивная реализация: F(0) = 0, F(1) = 1, F(n) = F(n-1) + F(n-2).

**Сложность:** O(2^n) — экспоненциальная, так как каждый вызов порождает два новых вызова, и множество подзадач пересчитывается многократно.

**1.3. Числа Фибоначчи (с мемоизацией)**

Рекурсивная реализация с сохранением уже вычисленных значений в словаре memo.

**Сложность:** O(n) — каждое число Фибоначчи вычисляется ровно один раз, повторные обращения возвращают сохранённый результат.

**1.4. Ханойские башни**

Рекурсивное решение задачи о Ханойских башнях: перенести n дисков с исходного стержня на целевой с использованием вспомогательного.

**Формула числа перемещений:** 2^n - 1

Алгоритм:
1. Перенести n-1 дисков на вспомогательный стержень
2. Перенести самый большой диск на целевой стержень
3. Перенести n-1 дисков со вспомогательного на целевой

**Сложность:** O(2^n)

## Сравнение наивной рекурсии и мемоизации

Таблица числа вызовов функции для вычисления чисел Фибоначчи:

| n  | F(n)   | fib_naive (вызовов) | fib_memo (вызовов) |
|----|--------|---------------------|-------------------|
| 5  | 5      | 15                  | 9                 |
| 10 | 55     | 177                 | 19                |
| 15 | 610    | 1,973               | 29                |
| 20 | 6,765  | 21,891              | 39                |
| 25 | 75,025 | 242,785             | 49                |
| 30 | 832,040| 2,692,537           | 59                |

**Анализ:**

- **Наивная рекурсия:** Число вызовов растёт экспоненциально. Для n=30 требуется почти 2.7 миллиона вызовов! Формула числа вызовов приблизительно равна 2·F(n) - 1, что соответствует экспоненциальному росту O(φ^n), где φ ≈ 1.618 (золотое сечение).

- **Мемоизация:** Число вызовов растёт линейно: для n=30 всего 59 вызовов. Каждое значение F(i) вычисляется максимум один раз, поэтому общее число вызовов ≈ 2n + 1 (прямые вызовы + проверки в memo).

**Выигрыш:** При n=30 мемоизация в **45,636 раз** быстрее по числу вызовов!

## Динамический массив (DynamicArray)

### Реализация

Динамический массив с ручным управлением ёмкостью:
- **Рост:** увеличение ёмкости вдвое при достижении size = capacity
- **Сжатие:** уменьшение ёмкости вдвое при size ≤ capacity/4 (не ниже INITIAL_CAPACITY = 4)
- **Счётчик копирований:** отслеживает число элементов, скопированных при смене буфера

### Инварианты

1. `0 ≤ size ≤ capacity` — всегда выполнен
2. Рост ёмкости строго в 2 раза
3. Элементы доступны по индексам `[0, size)`

### Амортизированный анализ методом учёта

**Метод учёта (банковский метод):**

Назначаем стоимость каждой операции `append`:
- **3 единицы** на один `append`
  - 1 единица — запись нового элемента
  - 2 единицы — «кредит» на будущее копирование

**Обоснование:**

При росте массива с ёмкости k до 2k копируется k элементов. На каждом из этих k элементов уже накоплено по 2 единицы кредита (они были добавлены операциями `append`). Таким образом:
- Накопленный кредит: 2k единиц
- Стоимость копирования: k единиц
- Остаток кредита: k единиц (достаточно для следующего роста)

**Вывод:** Средняя амортизированная стоимость `append` = **O(1)** (константа ≤ 3).

### Экспериментальные результаты

Замеры на сериях append различных размеров показали:

| n       | Копирований | (n + копирования)/n |
|---------|-------------|---------------------|
| 1,298   | 2,044       | 2.575               |
| 2,048   | 2,044       | 1.998               |
| 2,049   | 4,092       | 2.997               |
| 3,230   | 4,092       | 2.267               |
| 5,342   | 8,188       | 2.533               |
| 10,791  | 16,380      | 2.518               |
| 25,598  | 32,764      | 2.280               |
| 52,853  | 65,532      | 2.240               |
| 92,004  | 131,068     | 2.425               |
| 154,418 | 262,140     | 2.698               |

**Анализ:**

Величина `(n + копирования)/n` показывает общую стоимость в элементарных операциях (записи и копирования) на одну операцию `append`. Все значения находятся в диапазоне **[2.0, 3.0]**, что подтверждает амортизированную оценку O(1).

**Почему значения различаются?**

- Для n = 2^k (например, 2048): значение близко к 2.0, так как последний рост произошёл ровно при достижении этого размера.
- Для n = 2^k + 1 (например, 2049): значение близко к 3.0, так как только что произошло удвоение ёмкости и были скопированы все 2048 элементов.
- Для промежуточных значений: величина плавно изменяется между 2 и 3 в зависимости от «расстояния» до ближайшей границы роста.

## Стек (Stack)

### Реализация

Стек на базе `DynamicArray`, работает только через его публичный интерфейс:
- `push(value)` — делегирует `DynamicArray.append`
- `pop()` — делегирует `DynamicArray.pop`
- `peek()` — возвращает `DynamicArray.get(len - 1)`

### Свойства

- **LIFO** (Last In, First Out) — последним пришёл, первым вышел
- **Амортизированная сложность:** O(1) для всех операций (наследуется от `DynamicArray`)

------------------------------------------------------------------------

## Дек (Deque)

### Реализация

Дек на базе двусвязного списка:
- Каждый узел содержит `value`, `prev`, `next`
- Поддерживаются указатели `_head` и `_tail`
- Все четыре операции концов: `push_front`, `push_back`, `pop_front`, `pop_back`

### Свойства

- **FIFO/FILO** — двусторонняя очередь
- **Сложность всех операций:** O(1) (без амортизации!)
- **Инварианты:**
  - При пустом деке: `_head = _tail = None`
  - При одном элементе: `_head = _tail`
  - Двусвязность: `node.next.prev = node` и `node.prev.next = node`

## Сравнение с эталонными реализациями

### Вставка в начало (при размере n)

| Структура                  | n=1K    | n=3K    | n=10K   | n=30K   | n=100K  | Наклон |
|----------------------------|---------|---------|---------|---------|---------|--------|
| list.insert(0, x) + pop()  | 4.45e-07| 1.22e-06| 4.61e-06| 1.33e-05| 5.09e-05| 1.03   |
| deque.appendleft + pop     | 7.08e-08| 7.00e-08| 7.25e-08| 7.12e-08| 8.78e-08| 0.04   |
| Deque.push_front + pop_back| 4.96e-07| 6.20e-07| 4.82e-07| 5.27e-07| 4.92e-07| -0.02  |

### Удаление из начала (при размере n)

| Структура                  | n=1K    | n=3K    | n=10K   | n=30K   | n=100K  | Наклон |
|----------------------------|---------|---------|---------|---------|---------|--------|
| list.append + pop(0)       | 1.67e-07| 5.24e-07| 1.94e-06| 6.22e-06| 2.75e-05| 1.10   |
| deque.append + popleft     | 6.01e-08| 6.04e-08| 8.03e-08| 6.31e-08| 6.36e-08| 0.01   |
| Deque.push_back + pop_front| 7.21e-07| 4.76e-07| 5.31e-07| 5.11e-07| 5.38e-07| -0.04  |

### Анализ

**1. list.insert(0, x) и list.pop(0) — O(n):**

Наклон ≈ 1.0 в log-log осях подтверждает линейную зависимость от размера. При вставке в начало массива необходимо сдвинуть все n элементов вправо, при удалении из начала — сдвинуть все оставшиеся элементы влево. Это классический O(n).

**2. collections.deque и Deque — O(1):**

Наклон ≈ 0 означает, что время операции не зависит от размера структуры. Это достигается благодаря двусвязному списку, где добавление/удаление с любого конца требует только переназначения указателей, без сдвига элементов.

**3. Почему свой Deque медленнее collections.deque в 5-7 раз?**

- `collections.deque` реализован на C и оптимизирован
- Наша реализация на Python включает накладные расходы на:
  - Создание объектов `_Node` (выделение памяти, инициализация)
  - Интерпретацию Python-кода
  - Операции с атрибутами объектов

**Важно:** Постоянный множитель различается, но **асимптотика одинакова** — O(1).
